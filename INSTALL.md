# Установка для агента

Эта инструкция применяется, когда пользователь поручил установить или адаптировать скилл. Само чтение репозитория для обзора не является командой на установку.

## 1. Получить всю папку скилла

Установи целиком `skills/debate/`, включая `references/`, `scripts/`, `settings.json` и метаданные. Одного `SKILL.md` недостаточно. Используй штатный установщик или скопируй папку в каталог скиллов своей среды. Проверь Python 3.10+ (`python --version`; на некоторых системах команда `python3`). Сторонние Python-пакеты не требуются.

В Codex используй `$skill-installer` со ссылкой на `skills/debate`. В других средах проверь локальную документацию подключения скиллов; не угадывай каталог или поддержку команд. Если среда не поддерживает скиллы, подключи `SKILL.md` как именованную инструкцию, сохранив доступ к его относительным ссылкам. Не переписывай Python только из-за смены модели.

Если `debate` уже установлен, сравни версии и сохрани локальные настройки. При поручении обновить замени инструкции и помощник, сохранив выбранный корень данных; не перезаписывай существующую пользовательскую адаптацию без разбора различий.

## 2. Настроить общую папку данных

Сначала проверь явно указанный пользователем путь и существующий `DEBATE_HOME`. Если другая модель уже ведет обсуждения, подключись к той же папке: используй указанную пользователем существующую настройку. Если путь неизвестен, запроси его один раз. Для первой установки без существующей истории допустим стандартный `~/Debates`.

Сохрани выбранный путь в установленном `settings.json` как `data_root` либо используй уже настроенный `DEBATE_HOME`. На Windows для JSON удобны прямые слеши, например `D:/AI/Debates`; это пример, не предписание. Не сохраняй настройки компьютера в публичном репозитории. Обновление скилла не должно создавать новый реестр вместо прежнего или переносить обсуждения без поручения.

## 3. Адаптировать привязку к сеансу

Помощник использует `CODEX_THREAD_ID`, а при его отсутствии — текущую рабочую папку. В Codex сохрани штатное поведение.

Для другой среды настрой в ее локальной инструкции передачу `--scope` перед подкомандой. Используй постоянный идентификатор среды и реального разговора, если он доступен, либо постоянное имя выбранного пользователем рабочего контекста, например `gemini:project-one`. Запомни его в этой среде и повторяй при следующих вызовах. Не придумывай новый ID при каждом ходе и не передавай содержимое разговора в качестве ID.

```text
python -X utf8 <путь-к-скрипту> --scope "gemini:project-one" use --task "Название" --participant B
```

Общая папка данных должна совпадать у участников; `scope` разных сеансов должен различаться. Иначе агенты без собственного ID, запущенные из одной папки, будут делить одну привязку и перезаписывать сохраненную метку участника. При первой передаче пользователь задает B; при нескольких обсуждениях — название задачи. После этого достаточно команды продолжить. Метки A/B не переключают фактическую модель.

## 4. Проверить установку

- Проверь наличие всех файлов и относительных ссылок.
- Выполни `list` помощника и убедись, что он показывает ожидаемый корень данных. Чтение пустого списка не создает задачу.
- Если нужны пробы создания и продолжения, используй отдельную временную папку через `--root`; не добавляй тестовые задачи в историю пользователя.
- Сообщи путь установленного скилла, общую папку данных и способ его вызова в этой среде.

Сохрани обязательное интервью и явное подтверждение постановки, один ход за запуск, чтение всей истории, подписи участников, конструктивную критику, запись реальных ответов пользователя и итог только по его команде. Адаптация меняет подключение к среде, а не эти правила. Если агент не может писать файлы или запускать команды, прямо укажи ограничение; не утверждай, что установка выполнена.
