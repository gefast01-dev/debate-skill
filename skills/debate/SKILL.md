# Debate

Процесс: интервью → по одному ходу обсуждения → итог по команде пользователя. Пользователь вручную запускает модели; не запускай других агентов или фоновые раунды. Используй прямые двойные кавычки.

## Команды и поиск задачи

Понимай команды по смыслу. Ответы на вопросы принимай без повторения `$debate`.

| Команда после `$debate` | Действие |
| --- | --- |
| *(пусто / без аргументов)* | Проверить статус текущей задачи и предложить интерактивный выбор действий. |
| `новая задача: ...` | Новая папка, участник A, интервью. При отсутствии текста запроси его. |
| `B продолжай` / `модель A продолжай` | Следующий шаг выбранной задачи с указанной меткой. |
| `продолжай` | Сохраненные задача и участник. |
| `задача "Название" B продолжай` | Выбрать задачу по названию и продолжить как B. |
| `список` / `статус` / `выбери "Название"` | Просмотр или выбор без нового хода. |
| `итоги` / `подводи итоги` | Записать итог после согласования постановки. |
| `update` / `обнови скилл` | Сначала сверить с `gefast01-dev/debate-skill`, затем обновить измененные файлы скилла. |

### Интерактивное меню без аргументов

При вызове `/debate` или `$debate` без параметров запусти `status` и предложи нумерованный список действий по текущей стадии. Порядок и формулировки вариантов должны быть одинаковыми во всех средах:

- `ready_to_finalize`: 1) Подвести итоги и создать `03_result.md`; 2) Продолжить обсуждение следующим участником; 3) Показать статус и журнал; 4) Создать новую задачу; 5) Выбрать другую задачу.
- `discussion`: 1) Продолжить обсуждение следующим участником; 2) Показать статус и открытые вопросы; 3) Создать новую задачу; 4) Выбрать другую задачу.
- `interview` / `awaiting_confirmation`: 1) Ответить на вопросы или подтвердить постановку; 2) Показать текущую постановку; 3) Создать новую задачу.
- `completed`: 1) Открыть `03_result.md`; 2) Возобновить обсуждение; 3) Создать новую задачу; 4) Показать список задач.
- Нет активной задачи: 1) Создать новую задачу; 2) Выбрать задачу из списка.

Если среда поддерживает интерактивный опрос, используй его и одновременно продублируй варианты цифрами в чате. Получив выбор, сразу выполни его без повторного запроса. На стадии `discussion` не предлагай итоги: сначала требуется проверка или иной содержательный ход. Итоги доступны как первый вариант только на `ready_to_finalize`.

### Обновление скилла

Для `$debate update` сначала запусти `scripts/update_from_github.py --check`. Если изменений нет, сообщи, что скилл актуален. Если они есть, покажи список файлов и в рамках этой явной команды сразу выполни `--apply`; скрипт повторно проверит содержимое перед записью. Не обновляй скилл по обычной команде "продолжай".

```text
python -X utf8 <skill>/scripts/update_from_github.py --check
python -X utf8 <skill>/scripts/update_from_github.py --apply
```

Скрипт обновляет только `SKILL.md`, `agents/`, `references/`, `scripts/` и `assets/` из `https://github.com/gefast01-dev/debate-skill`. Он не удаляет локальные файлы, сохраняет `settings.json` и не касается папки `Debates`. Для вызова нужны доступ к сети и разрешение на запись в каталог скиллов. После обновления укажи, что новые инструкции применятся со следующего вызова `$debate`; если среда не подхватила изменение автоматически, попроси перезапустить ее.

A/B — постоянные подписи, а не переключатели моделей. Не имитируй чужие ходы и не угадывай фактическую модель. При известном несоответствии метки модели уточни метку; разные буквы сами по себе не доказывают независимость участников.

Используй [scripts/debate_state.py](scripts/debate_state.py), Python 3.10+. Путь к скрипту — относительно этого скилла. Корень берется из [settings.json](settings.json); не меняй его с рабочим каталогом. Явные `DEBATE_HOME`/`--root` переопределяют корень. При недоступности сообщи причину, не создавай другой реестр.

```text
python -X utf8 <script> new --title "Название" --source-file <UTF-8-файл> --participant A
python -X utf8 <script> use [--task "Название или ID"] [--participant B]
python -X utf8 <script> list
python -X utf8 <script> status [--task "Название или ID"]
python -X utf8 <script> phase --task <id> --value <стадия>
```

Квадратные скобки обозначают необязательные аргументы. Исходный текст подготовь файловым инструментом в `work/`; не вставляй его в исполняемый shell-код. Скрипт создает только первый файл и реестр; содержание остальных записываешь ты.

Для продолжения вызывай `use`: явно указанная задача → привязка текущей задачи Codex → единственная незавершенная задача. При неоднозначности покажи названия и запроси выбор; не выбирай последнюю по времени. Привязка определяется `CODEX_THREAD_ID`, иначе абсолютным рабочим каталогом; `--scope` используй только для явной привязки или тестирования. При смене задачи сохраняются ее история и номера.

## Файлы и переходы

- `01_task.md`: исходный текст, интервью, уточненная постановка и подтверждение пользователя.
- `02_discussion.md`: полный журнал; создается после подтверждения постановки, пополняется без переписывания истории.
- `03_result.md`: самостоятельный результат по явной команде пользователя.

После выбора прочитай целиком `01_task.md` и существующий `02_discussion.md`, включая ответы пользователя. Неполная история не позволяет объявлять согласие; запроси недостающее или согласованное сокращение. Реестр помогает найти файлы, но его `phase` не заменяет реальные сообщения и подтверждения пользователя.

Читай только инструкцию нужного этапа:

- Постановка не подтверждена → [interview.md](references/interview.md). До подтверждения никаких решений и журнала, даже по команде "итоги".
- Постановка подтверждена, нужен очередной ход → [discussion.md](references/discussion.md).
- Пользователь явно поручил итог → [finalize.md](references/finalize.md). Рекомендация модели не является поручением.
- Только список, статус или выбор → без содержательного хода; статус включает последний ход, открытые вопросы и следующее действие.

"Продолжай", смена модели и молчание не заменяют ответ на ожидаемый вопрос или подтверждение постановки. После завершения "продолжай" возобновляет обсуждение; прежний итог сохраняется до команды обновить его.

В начале обозначь задачу и участника. После записи проверь сохраненное, затем обнови `phase` и дай вердикт в чате. Стадии: `interview`, `awaiting_confirmation`, `discussion`, `awaiting_user`, `ready_to_finalize`, `completed`. После прерывания восстанови состояние по файлам; не дублируй сохраненный ход из-за отставшего реестра.
